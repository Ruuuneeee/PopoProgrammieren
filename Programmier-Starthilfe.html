    Kapitel 1

    Das große Bild

    Bevor es um einzelne Befehle geht, verschaffst du dir hier den Überblick: Welche Werkzeuge gibt es, welchen Weg nimmt dein Code, und was machst du wann?

    Drei Begriffe zum Start

    • Git

      Ein Programm, das Versionen deiner Dateien speichert. Wie Speicherstände in einem Videospiel: Du siehst jederzeit, was sich wann geändert hat, und kannst zu einem alten Stand zurück.

    • GitHub

      Eine Webseite, auf der du deine Versionsgeschichte online ablegst. Wie eine Cloud (iCloud, Google Drive), nur speziell für Git.

    • SSH-Key

      Der Ausweis, mit dem sich dein Laptop bei GitHub anmeldet. So kannst nur du in deine Repositorys hochladen.

    Der Weg deines Codes

    Deinen Code schreibst du in Eclipse. Bis er bei GitHub ankommt, braucht es vier Schritte. Die Befehle dafür tippst du in PowerShell ein, dem Terminal von Windows.

    Unterwegs macht dein Code zweimal Station auf deinem Laptop: im Index, einer Art Packliste, und im lokalen Repository. Probier es unten selbst aus.

    SchrittBefehlWas passiertWo ist dein Code danach?
    1–Du schreibst Code in Eclipse und speicherst.im Projektordner auf deinem Laptop
    2git add .Du legst die Änderungen auf die „Packliste“ für den nächsten Speicherstand.im Index (Staging Area)
    3git commit -m "…"Du legst einen Speicherstand an.im lokalen Repository, nur auf deinem Laptop
    4git pushDu lädst die Speicherstände hoch.auf GitHub, also online

    Merke

    Ein Commit liegt nur auf deinem Laptop. Erst git push lädt ihn zu GitHub hoch. Vorher sieht ihn dort niemand, auch nicht die Tutor:innen.

    Mit jedem Commit kommt ein neuer Speicherstand dazu. So wächst Schritt für Schritt deine Versionsgeschichte.

    Mathe-Ecke: Die Geschichte als Kette

    Jeder Commit merkt sich seinen Vorgänger. Arbeitest du allein auf einem Zweig, entsteht eine Kette: Der neueste Commit verweist auf den davor, der wieder auf seinen Vorgänger, bis zum allerersten. Das erinnert an eine rekursiv definierte Folge, bei der jedes Glied auf das vorherige verweist.

    Genau genommen ist die Geschichte immer ein gerichteter azyklischer Graph (DAG), die Kette ist nur sein einfachster Fall: Die Kanten zeigen vom Commit zu seinen Vorgängern, und wer ihnen folgt, kommt nie wieder am Ausgangspunkt an. Werden zwei Zweige zusammengeführt, hat ein Commit zwei (selten mehr) Vorgänger.

    Was mache ich wann?

    Nicht alles musst du jedes Mal machen. Manches richtest du nur einmal ein, anderes wiederholst du ständig.

    1. Einmal pro Laptop

      Git installieren, den Standard-Branch auf main setzen, Name und E-Mail eintragen, einen SSH-Key erzeugen und bei GitHub hinterlegen. Alles dazu steht unten in deiner Start-Checkliste.

    2. Für jedes Übungsblatt

      Ein leeres Repository auf GitHub anlegen und ein Java-Projekt in Eclipse. Mit git init machst du das Projekt zu einem Repository. Mit git remote add origin … verbindest du es mit seiner Online-Kopie, dem Remote namens origin. Mehr dazu in Abschnitt 2 der Git-Starthilfe deiner Veranstaltung.

    3. Nach jeder Änderung

      git add ., dann git commit -m "…", dann git push. Der Push ist der Schritt, der deine Arbeit zu GitHub bringt. Mehr dazu in Abschnitt 3 der Git-Starthilfe.

    Tipp: Beim zweiten Mal wird es kürzer

    Beim ersten Hochladen eines Projekts schreibst du git push -u origin main. Das -u merkt sich, dass dein main zu origin/main gehört. Danach reicht ein einfaches git push.

    Deine Start-Checkliste

    Diese Schritte erledigst du einmal pro Laptop, danach musst du dich nicht mehr darum kümmern. Hak ab, was du geschafft hast. Die Häkchen bleiben in diesem Browser gespeichert.

    Vorsicht: Der Private Key bleibt bei dir

    ssh-keygen erzeugt zwei Dateien. Der Private Key (id_rsa) bleibt immer auf deinem Laptop: nie weitergeben, nie hochladen. Bei GitHub hinterlegst du nur den Public Key (id_rsa.pub), den darf jeder sehen.

    Stolperfalle: git wird nicht erkannt

    Meldet PowerShell nach der Installation, dass git nicht erkannt wird, schließ das Fenster und öffne ein neues. Ein Fenster, das schon vor der Installation offen war, bekommt sie nicht mit.
